## How I investigate an incident

Aligned to the CySA+ incident response domain and NIST SP 800-61.

```
  01 Detection  →  02 Triage  →  03 Analysis  →  04 Containment
                                                      ↓
       07 Lessons learned  ←  06 Recovery  ←  05 Eradication
```

| Phase | What I actually do |
|---|---|
| **01 · Detection** | Capture the signal accurately before it's lost — alert source, rule, exact timestamps, raw telemetry snapshot |
| **02 · Triage** | True positive, false positive, or benign true positive? Scope the hosts, users and accounts touched; assign severity; escalate early rather than late |
| **03 · Analysis** | Correlate host, network and identity telemetry into one timeline; establish initial access; collect and enrich IOCs; map behaviour to MITRE ATT&amp;CK; state confidence honestly |
| **04 · Containment** | Isolate hosts, disable compromised accounts, block attacker infrastructure — without destroying the evidence needed to understand it |
| **05 · Eradication** | Remove malware, persistence and rogue accounts; patch the exploited weakness; rotate exposed credentials; re-scan to confirm |
| **06 · Recovery** | Restore from known-good state, validate integrity, heighten monitoring, define what "closed" means |
| **07 · Lessons learned** | Timeline, root cause and impact in plain language; what detection missed and why; new or tuned rules; actions with owners and dates |

Full write-up: [`investigation-methodology.md`](./incident-investigations/investigation-methodology.md) · Reusable [incident report template](./incident-investigations/incident-report-template.md)
